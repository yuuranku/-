# PALIS × Win95 管理员与书记官工作台设计规格

**日期：** 2026-07-28

**状态：** 已获方向确认，待用户复核本文

**适用范围：** 管理员工作台、书记官工作台及其窗口外壳

**不适用范围：** PALIS 首页、九类公开档案目录、九类正式档案正文排版

## 1. 设计结论

管理员与书记官工作台采用“PALIS × Win95 混合”方案：保留现有深色极地桌面、PALIS 红蓝标记、现有字体、图标、纸张排版和动效语言，只强化 Win95 的桌面外壳与操作反馈。

这不是把站点改成一套仿 Windows 主题，也不是复制一套新的工作流。九类档案入口、草稿、审核回信、审核与录入、账号管理、档案管理仍调用现有业务处理器；开始菜单、桌面图标和任务栏只是同一批操作的不同入口。

## 2. 目标与非目标

### 2.1 目标

1. 用户进入工作台后，能立即识别出 Win95 式桌面、窗口和任务栏。
2. 管理员与书记官共用同一套视觉组件，只由权限决定名称和可见功能。
3. 所有入口都有可观察的默认、悬停、键盘聚焦、按下、选中、禁用、加载、成功和失败状态。
4. 保留九类档案现有排版；工作台升级不得改变公开档案的目录模式、字体、色彩和动效。
5. 不增加外部字体、图片、UI 框架或网络请求，对免费服务器不形成额外运行负担。

### 2.2 非目标

1. 不把深色 PALIS 桌面替换成 Win95 经典青绿色桌面。
2. 不模拟操作系统文件管理、磁盘、回收站或无业务用途的装饰程序。
3. 不为开始菜单复制第二套权限判断、窗口状态或表单状态。
4. 不修改档案数据结构、审核状态机、编号规则或本地管理员安全边界。
5. 不引入 Tailwind、React、Radix、Base UI 或新的动效曲线。

## 3. 视觉系统

### 3.1 保留的 PALIS 特征

- 深色工作台背景和冷色极地氛围。
- 红、黄、青三色识别标记。
- 现有中文字体、等宽字体和档案纸张字体。
- 九类档案 SVG 图标与编号 `01–09`。
- 现有弹窗出现、最小化、还原和关闭动效；减少动态模式继续生效。

### 3.2 强化的 Win95 特征

- 使用统一的四级灰立体边框：高光、面板、中灰阴影和深色阴影。
- 活动窗口采用 PALIS 深海军蓝标题栏与浅色文字；非活动窗口采用中灰标题栏。
- 标题栏按钮使用 Win95 式方形凸起边框，并提供按下后的内凹状态。
- 任务栏固定于工作台底部，包含开始按钮、任务按钮区、身份/频道状态、返回档案系统和托盘时钟。
- 桌面图标获得蓝色选中底、点状键盘焦点框、按下位移和清晰的禁用状态。
- 窗口内容继续使用现有纸张或管理面板样式，不把正文变成仿系统控件。

新增样式必须通过工作台作用域选择器生效，禁止修改全局 `button`、`input`、`.title-bar` 或公开档案选择器。

## 4. 共享组件边界

工作台只新增或整理以下共享外壳，不复制业务页面：

1. **WorkspaceShell**：工作台背景、身份标题、九类桌面图标区域、工具入口区域和任务栏。
2. **WorkspaceWindowChrome**：活动/非活动标题栏、窗口控制按钮、边框、层级和焦点状态。
3. **WorkspaceStartMenu**：按当前身份列出已有入口；每一项转发到既有桌面图标或工作流面板处理器。
4. **WorkspaceTaskbar**：显示已打开窗口；点击活动任务最小化，点击非活动或已最小化任务恢复并置顶。
5. **WorkspaceDesktopIcon**：保留现有九类 SVG，只统一选择、聚焦、打开和禁用反馈。
6. **WorkspaceRoleConfig**：仅描述角色名称和入口可见性，不保存业务数据。

工作台内部层级固定为五档，不再混用任意常量：桌面与图标、普通窗口、任务栏、开始菜单、阻塞确认。窗口只允许在“普通窗口”档内递增；危险确认始终位于最高档。

管理员与书记官不得拥有两套 DOM 模板或两套 CSS。身份差异由会话上下文和现有权限函数决定：

- 书记官：九类档案入口、暂存箱、审核回信。
- 管理员：书记官全部入口，以及审核与录入、账号管理、档案管理。
- 科考站与白幕入口：书记官进入后只能发起对既有档案的修改；管理员可创建、修改和配置。

## 5. 按钮与交互逻辑

### 5.1 工作台入口与退出

- `书记官工作台 / 管理员工作台`：验证会话与角色后打开工作台；不满足权限时保持关闭并显示现有拒绝反馈。
- `返回档案系统`：关闭所有工作台浮层并返回进入前的 PALIS 页面位置；不删除草稿，不重置 IndexedDB。

### 5.2 开始按钮与开始菜单

- 单击开始按钮：切换菜单开关并同步 `aria-expanded`。
- 再次单击、单击菜单外、按 `Escape` 或退出工作台：关闭菜单。
- 菜单项只触发现有入口的同一个打开函数，不直接读写档案。
- 菜单中不得显示当前角色无权使用的项目；不能只做视觉隐藏后仍允许键盘触发。
- 菜单按固定顺序分为三组：身份与欢迎、九类档案、工作流工具；底部固定提供“返回档案系统”。
- “九类档案”使用一级子菜单列出 `01–09`，不在打开开始菜单时加载九个编辑器。
- 书记官工作流工具为“暂存箱、审核回信”；管理员在此基础上增加“审核与录入、账号管理、档案管理”。

### 5.3 九类桌面图标

- 单击：设为当前选择并立即打开对应档案编辑窗口，保留现有站点操作习惯。
- 键盘聚焦：只更新点状焦点框；按 `Enter` 或 `Space` 打开对应档案编辑窗口。
- 双击不会重复建立窗口；第二次点击只激活已经打开的同一档案窗口。
- 科考站、白幕入口在书记官身份下打开“申请修改”空白编辑页，不出现“新增档案”动作。

### 5.4 窗口控制

- 标题栏：活动窗口为海军蓝，非活动窗口为中灰；单击窗口任意可交互区域会将其置顶。
- 最小化：窗口退出桌面可视区域但保留任务栏按钮和未保存表单状态。
- 还原：恢复原尺寸、位置、滚动位置和表单状态，并置于最前。
- 最大化：仅桌面宽屏提供；再次单击恢复上一次位置和尺寸。
- 关闭：关闭当前窗口并移除任务栏按钮；存在未保存内容时使用现有确认机制。
- 任务栏按钮：活动窗口单击后最小化；已最小化或非活动窗口单击后还原并置顶。
- 打开窗口：焦点进入窗口标题或首个可操作控件；模态窗口打开时 `Tab` 不得逃到工作台外。
- 关闭窗口：焦点返回触发它的桌面图标、菜单项或任务栏按钮。

窗口控制按钮必须使用文本或现有 CSS 图形，不新增远程图片。所有按钮必须具备中文 `aria-label`。

### 5.5 加载、错误和成功反馈

- 请求进行中：触发按钮禁用并保留原标签，同时在邻近状态区显示具体动作。
- 成功：在当前窗口内显示结果和下一步，不依赖仅颜色表达。
- 失败：保留用户已经填写的内容，显示可理解的错误说明和重试入口。
- 权限变化：立即关闭已经失去权限的管理菜单；不得让隐藏窗口继续执行管理员动作。
- 状态消息使用 `aria-live` 或 `role="status"`；字段错误同步设置 `aria-invalid` 和 `aria-describedby`。
- 删除账号、永久删档等危险动作使用 PALIS × Win95 的 `role="alertdialog"` 确认窗，必须同时提供明确的“取消”和“确认”按钮；不再调用 `window.confirm()`。

## 6. 响应式与无障碍

### 6.1 桌面

- 以 `1440×900` 为主要验收尺寸。
- 九类入口保持可扫描的网格；欢迎窗口不得遮住全部入口。
- 任务栏不得覆盖窗口的主要提交按钮。

### 6.2 移动端

- 以 `390×844` 为主要验收尺寸。
- 九类入口采用两列或三列自适应网格，最小触控区域为 `44×44px`。
- 工作流窗口占满任务栏上方可用区域，不允许窗口拖到屏幕外。
- 输入框、选择器和主要按钮高度不低于 `44px`；移动端输入文字不低于 `16px`，避免系统自动缩放。
- 开始菜单限制在安全区域内；任务按钮区允许横向滚动，但开始、返回和时钟始终可用。
- 顶、右、底、左四边均使用 `safe-area-inset-*`；新增高度计算使用 `dvh`，不新增 `vh`。
- `844×390` 等短屏横向布局必须可滚动且不重叠；移动端禁止拖动窗口。
- 不依赖悬停显示必要信息。

### 6.3 键盘与减少动态

- `Tab` 顺序遵循：开始按钮 → 桌面图标 → 工具入口 → 已打开窗口 → 任务栏。
- `Escape` 优先关闭开始菜单，其次关闭当前非阻塞弹窗，不直接退出工作台。
- 所有交互元素有清晰 `:focus-visible`。
- `prefers-reduced-motion: reduce` 下停用装饰性过渡，功能状态立即完成。
- 新增过渡不超过 `200ms`，只使用 `opacity` 和 `transform`，不得新增持续运行的装饰动画。

## 7. 性能与免费服务器影响

该升级为静态 HTML/CSS 与少量事件转发，不增加数据库表、API、定时轮询、WebSocket、外部字体或图片。

验收预算：

- 生产 JavaScript gzip 增量目标不超过 `8 KB`。
- 生产 CSS gzip 增量目标不超过 `6 KB`。
- 不新增任何外网请求。
- 工作台关闭时不运行新的动画循环或计时器。
- 开始菜单不预加载九个 iframe；仍在实际打开编辑窗口时按需加载。

## 8. 与档案系统的耦合方式

Win95 外壳只负责“显示入口、打开窗口、反映窗口状态”，不直接操作档案记录。

```text
桌面图标 / 开始菜单
        ↓ 同一动作标识
现有 Workspace 控制器
        ↓ 统一仓储合同
Supabase 仓储 或 本地 IndexedDB 仓储
        ↓
草稿 → 提交 → 审核 → 正式录入 → 九类公开档案
```

因此后续重写仓储、自动编号和本地管理员运行时，不需要再次改造工作台按钮；工作台也不能绕开统一仓储合同直接访问 Supabase。

## 9. 实施顺序

1. 先完成可重复的旧工作台桌面/移动端截图基线。
2. 建立共享工作台外壳 token 和作用域，消除互相冲突的工作台专用覆盖。
3. 将管理员与书记官入口统一为角色配置，不改变现有元素 ID 和业务处理器。
4. 实现开始菜单、窗口活动态和任务栏状态转发。
5. 补全鼠标、键盘、移动端和减少动态状态。
6. 使用 `ui-checker` 做布局、状态、无障碍和移动端检查。
7. 使用 `ui-ux-pro-max` 的设计准则核验信息层级、目标尺寸、错误反馈与性能；不调用缺失的搜索脚本生成新主题。

## 10. 验收标准

1. 管理员和书记官两种身份均能完成各自全部既有流程。
2. 未授权入口在桌面、开始菜单、键盘顺序和直接调用四个层面都不可用。
3. 九类公开档案桌面/移动端稳定区域相对基线像素差不超过 `0.5%`。
4. 工作台视觉变化仅发生在工作台背景、图标状态、窗口外壳、开始菜单和任务栏。
5. `1440×900` 与 `390×844` 下无主要元素重叠、裁切或不可达。
6. `844×390` 短屏横向布局可滚动且不重叠，四边安全区有效。
7. 鼠标、键盘和触控均可打开九类入口、工作流面板、开始菜单和任务栏窗口。
8. 模态焦点不能逃出工作台；窗口打开后获得焦点，关闭后焦点返回原触发入口。
9. 科考站、白幕入口在书记官身份下没有新增动作；管理员仍可新增和配置。
10. 所有加载、成功、失败、禁用和权限拒绝状态可观察且不丢失已填写内容。
11. 危险确认具有可访问标题、说明、取消与确认动作，不调用浏览器原生确认框。
12. 生产构建无本地管理员专用代码、无新增外部请求，并满足本节性能预算。
13. 全量自动测试、生产构建、基线对比和人工 UI 检查全部通过后，方可更新验收报告为“通过”。
