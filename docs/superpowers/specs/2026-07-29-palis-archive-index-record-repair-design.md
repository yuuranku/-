# PALIS 档案索引与多文档修复设计

日期：2026-07-29  
状态：待书面复核  
适用项目：`10_地球仪Dashboard`

## 1. 目标

在保留九类公开档案现有排版、弹窗和动效的前提下，修复以下核心问题：

1. 新档案不再显示 `AUTO:<uuid>`，既有占位档号获得正式类别编号。
2. 新上层档案追加到现有目录队尾，并显示可由管理员逐档关闭的 `NEW` 标记。
3. 事件索引取消 26 个固定位置上限，新事件使用真实发生时间且不会重叠。
4. 物种可以明确选择植物、动物或复合群落，并进入正确索引轨道。
5. “向现有档案加入新文档”与“修改现有文档”成为两种不同流程。
6. 九类编辑器按可行性报告 v0.4 第 15 节填写合同生成索引，不再只依赖标题、摘要和发布时间。
7. 人物和事件文档支持受控图片槽位。
8. 书记官与管理员工作台完成 PALIS × Win95 混合风格，但不改变公开档案视觉。

## 2. 明确不做

- 不重做 PALIS 首页、九类公开目录的既有美术语言或正式档案正文排版。
- 不实现任意位置的富文本图片插入。
- 不部署生产环境；本轮只提交代码、数据库迁移和本地验收证据。
- 不把科考站、白幕入口的新建权限开放给书记官。
- 不让一份档案的自定义词条污染同类别其他档案。

## 3. 档案层级与流程

### 3.1 层级

```text
上层档案文件 S23
├─ 记录 01 · 书记官甲 · VER 0.1
│  ├─ 修改申请 01 · 书记官乙 · VER 0.2
│  └─ 修改申请 02 · 书记官丙 · VER 0.3
└─ 记录 02 · 书记官丁 · VER 0.1
```

- `archive` 是九类目录中的上层档案文件，持有正式档号和公开索引。
- 非 `amendment` 的已发布 `contribution` 是一份独立完整文档，对应一个“记录”标签。
- `amendment` 必须指向某一份独立文档；它显示在目标记录内部，不生成新的记录标签，也不计入记录数量。
- 对网站原有官方档案提交修改时，可以指向官方记录；该流程不凭空建立第二个上层文件。

### 3.2 三个编辑动作

| 动作 | 选择目标 | 编辑页面 | 发布结果 |
|---|---|---|---|
| 新建档案 | 无 | 对应类别的空白完整设定卡 | 新上层文件与记录 01 |
| 向现有档案加入新文档 | 选择上层档案 | 对应类别的空白完整设定卡 | 同一上层文件中的下一条独立记录 |
| 修改现有文档 | 先选上层档案，再选具体记录 | 空白自由修改页 | 归入目标记录的批准修订 |

向现有档案加入新文档时不加载旧记录内容。修改现有文档时不自动选择“最新记录”，必须由操作者明确选择目标记录。

## 4. 九类目录索引合同

现有九份 HTML 设定卡继续作为完整正文编辑器。工作台增加由类别配置生成的“目录归类与索引登记”区域；受控字段与设定卡对应字段双向同步，并保存为文档的 `indexData`。

| 类别 | 索引必填数据 |
|---|---|
| 国家 | 正式国名、档案时期、阵营/归档链 |
| 组织 | 正式名称、阵营通道、成立或首次确认时期 |
| 科考站 | 站名、纬度、经度、所属方、站点类型、当前状态 |
| 白幕入口 | 名称、纬度、经度、所属方、入口类型、当前状态、危险级 |
| 生态 | 名称、记录类型、首次记录时期、覆盖范围/所属地层、状态 |
| 人物 | 姓名/代称、档案归属、主要组织、职务、活跃时期/最后状态 |
| 事件 | 名称、开始时间、结束时间、时间精度、地点、复核状态 |
| 异常 | 名称、母事件、发生时间、地点、异常类型、严重度、卷内状态 |
| 物种 | 名称、植物/动物/复合群落、首次发现时间、地点、标本状态、危险级 |

发布新上层档案时，`indexData` 生成上层档案的公开索引投影。向现有档案加入新文档不会静默覆盖上层索引；修改索引必须由管理员在正式录入时明确确认。

## 5. 编号、排序与 NEW

- 正式档号只由本地事务引擎或 PostgreSQL 生成：`N`、`O`、`ST`、`EN`、`E`、`P`、`EV`、`A`、`S` 加类别顺序号。
- 前端不再发送可被保存的 `AUTO:<uuid>` 作为正式档号。
- 发布成功后，数据库返回的正式档号必须回写到上层档案、公开目录投影和当前窗口；九类卡片角标、文件名、窗口标题和详情抬头只能读取该正式档号，禁止从提交 UUID、贡献 ID 或附件名截取显示编号。
- 新迁移以事务方式修复既有 `AUTO:%` 档号，并避免与已有正式编号冲突。
- 远程数据库未安装所需发布能力时，正式录入必须失败并显示可理解的管理员提示，不能留下半成品。
- 网站原有静态档案保持原顺序；数据库新建的上层档案按类别顺序号升序追加到队尾。
- 新上层档案默认 `new_badge_visible = true`。向既有档案加入文档或批准修改不会重新打开标记。
- 管理员“正式档案管理”中的每张档案卡提供 `NEW 标记：开/关`，成功后立即刷新公开目录。

## 6. 事件与物种索引

### 6.1 事件

- 前 26 个档案保留现有手工构图。
- 第 27 个起使用确定性的溢出行布局，不再对 26 取模。
- 平面高度、缩放边界、缩略导航和可见数量均由实际布局数组计算。
- 新事件在访问顺序上追加到队尾；卡面年份取 `indexData.startDate`，禁止使用 `published_at` 代替事件时间。
- 本地验收覆盖 26、27、29 和 100 条事件；100 条时仍可缩放、平移和打开最后一条。

### 6.2 物种

- 分类使用受控值 `FLORA`、`FAUNA`、`COMPOSITE`。
- 设定卡中的分类文字与工作台选择器双向同步。
- `FLORA` 进入植物侧，`FAUNA` 进入动物侧，`COMPOSITE` 使用双轨标记并进入独立复合分组。
- 未选择分类不能提交新档案。

## 7. 图片

- 人物文档提供一个肖像槽位。
- 事件文档提供一个封面槽位和最多六个带说明的证据图槽位。
- 选择图片后在浏览器中转换为 WebP；最长边不超过 1600px，单张不超过约 800KB。
- 线上完整图片写入现有 `archive-attachments` Storage；文档只保存附件路径、用途、替代文字、说明和排序。
- 本地管理员模式在 IndexedDB 保存 Blob 与相同元数据。
- 公开目录只懒加载封面缩略图；完整证据图仅在打开所属文档后加载。
- 图片上传或转换失败不破坏文字草稿，失败项可以单独重试或移除。

## 8. 数据与接口

`archives` 增加：

- `index_payload jsonb not null default '{}'`
- `new_badge_visible boolean not null default false`

`archive_attachments` 增加：

- `role text`：`portrait`、`event-cover` 或 `event-evidence`
- `caption text`
- `alt_text text`
- `sort_order integer`

仓库合同增加：

- `setArchiveNewBadge(archiveId, visible)`
- `listArchiveDocuments(archiveId)`，只返回可以成为修改目标的官方记录和非修改文档。
- `listPublishedMedia(contributionId)`，返回已发布文档可读取的图片元数据和临时访问地址。

本地仓库与 Supabase 仓库实现同一合同。发布、索引写入、编号、版本、NEW 初始值和通知在同一个本地事务或数据库事务内完成。

## 9. 工作台视觉

只调整书记官和管理员工作台：

- 活动窗口使用 Win95 深蓝标题栏；非活动窗口使用灰色标题栏。
- 桌面图标、开始菜单、字段、下拉框、按钮、状态栏使用经典 3D 凸起/凹陷边框和点状焦点框。
- PALIS 的冷蓝、冷红、纸张色、扫描纹理和现有字体继续保留。
- “目录归类与索引登记”、目标记录选择器、图片槽位和 NEW 开关必须拥有默认、悬停、按下、聚焦、禁用、加载、成功和失败状态。
- 不修改九类 HTML 正文设定卡及公开档案窗口的既有美术排版。

## 10. 错误处理与性能

- 缺少索引必填项时，提交按钮保持可用但提交后聚焦第一个错误字段，并列出缺失项。
- 目标记录不存在、已离线或版本冲突时禁止提交修改申请。
- 目录读取只获取上层索引投影，不读取完整正文或证据图片。
- 公开目录按最多 100 条一批读取；图片懒加载并使用浏览器缓存。
- 任一步发布失败都不留下已发布贡献、孤立版本或部分索引。

## 11. 本地验收

使用唯一的本地管理员账号完成：

1. 新建异常，得到 `A<number>`，正常显示标题，不出现 `AUTO:`。
2. 新建物种后，列表角标、窗口标题和详情抬头均显示同一个 `S<number>`，不显示 UUID 片段。
3. 新档案位于队尾并带 `NEW`；管理员关闭后刷新仍保持关闭。
4. 发布第 27、29 条事件，最后一条可见、可选、可打开，年份来自事件时间。
5. 分别发布植物、动物、复合群落，进入对应分组。
6. 向同一物种加入第二份完整文档，出现记录 02 且正文正确。
7. 对记录 01 提交修改，修改显示在记录 01 内部，记录总数仍为 2。
8. 人物肖像和事件证据图经过压缩、保存、审核后可以重新打开。
9. 书记官视角不能新建科考站和白幕入口；本地管理员可以。
10. 工作台通过桌面与窄屏截图检查，公开九类页面与既有视觉基线无非预期变化。
