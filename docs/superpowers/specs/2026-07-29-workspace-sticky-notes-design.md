# PALIS 工作台共享便签条设计规格

日期：2026-07-29

状态：用户已确认，待用户复核书面规格后纳入实现计划。

## 1. 目标

替换工作台右侧的欢迎说明窗，提供一组贴在屏幕右侧的共享便签条。管理员可以新增、编辑标题和内容、删除便签；书记官可以查看并在当前桌面会话中关闭单张便签，但不能编辑内容。

左侧工作台图标同步放大，使其更容易辨认和点击。

## 2. 已确认的交互规则

### 2.1 便签内容

- 初始状态没有默认文案或预置便签，右侧保持空白。
- 管理员可创建任意多张便签；每张包含标题和正文。
- 管理员可修改或删除任意共享便签。
- 书记官只能读取标题和正文，不能新增、编辑或删除共享便签。
- 便签内容在 Supabase 正式模式下跨账号同步；`LOCAL` / IndexedDB 只用于单机演示。

### 2.2 位置、拖动与关闭

- 未保存位置的便签默认从屏幕右侧按顺序纵向堆叠，像贴在桌面上的便签条。
- 管理员和书记官都可拖动每张便签。
- 便签拖动后的 `left`、`top` 位置按“账号 + 便签”长期保存；同一便签在不同账号下可有不同位置。
- 书记官可以关闭单张便签。关闭只在当前一次桌面打开期间生效，不写入数据库；重新打开桌面后，该便签重新显示在该账号保存的位置。
- 窄屏上便签仍可拖动，但坐标会被限制在任务栏上方可见区域内，避免无法找回。

### 2.3 视觉与桌面层级

- 便签是轻量纸质便签条，不是原来的白色欢迎窗口，也不是正文编辑器窗口。
- 每张便签有独立标题、小型关闭控制和纸张阴影；管理员额外看到“新增便签”和“编辑”控制。
- 管理员控制仅在便签区域显示，不新增书记官的第三个主桌面图标。
- 左侧图标图形为 `60px`，完整点击区域至少 `96×96px`。
- 书记官桌面的两项主任务仍只有“新增档案”和“修改档案”；管理员保留审核、档案管理和账号管理入口。

## 3. 数据与权限设计

新增两组持久化数据，而不影响现有档案、审批和发布状态机：

```text
workspace_notes
  id, title, content, sort_order, created_by, created_at, updated_at

workspace_note_layouts
  note_id, profile_id, left_px, top_px, updated_at
  primary key (note_id, profile_id)
```

- `workspace_notes` 是所有工作台账号可读取的共享内容；仅已启用管理员可新增、修改、删除。
- `workspace_note_layouts` 是个人布局；已启用管理员和书记官只能读取/写入自己的 `profile_id` 行。
- 服务端 API 使用现有仓库边界，新增：

  ```js
  listWorkspaceNotes() => Promise<WorkspaceNote[]>;
  createWorkspaceNote({ title, content, sortOrder }) => Promise<WorkspaceNote>;
  updateWorkspaceNote(id, { title, content, sortOrder }) => Promise<WorkspaceNote>;
  deleteWorkspaceNote(id) => Promise<{ id }>;
  listWorkspaceNoteLayouts(profileId) => Promise<WorkspaceNoteLayout[]>;
  saveWorkspaceNoteLayout({ noteId, profileId, leftPx, topPx }) => Promise<WorkspaceNoteLayout>;
  ```

- 便签关闭集合为浏览器会话内的 `Set<noteId>`，不会调用持久化 API。

## 4. 组件和数据流

```text
管理员编辑便签
  → repository create/update/delete
  → Supabase workspace_notes
  → 所有账号下次/再次加载工作台时 listWorkspaceNotes
  → 右侧共享便签条

任意账号拖动便签
  → 限制在可见桌面区域
  → saveWorkspaceNoteLayout(账号自己的坐标)
  → 下次进入工作台恢复该账号的坐标

书记官关闭便签
  → sessionClosedNoteIds.add(noteId)
  → 当前会话隐藏
  → 重新打开桌面后重新显示
```

## 5. 失败处理与验收

- 加载共享便签失败时，右侧显示非阻塞“便签暂不可读取”状态和重试按钮；不能影响档案新增、修改或审核。
- 保存管理员编辑失败时保留输入内容，显示错误并允许重试。
- 保存个人拖动位置失败时便签留在当前视觉位置，并提示位置未同步；下次打开回落到上一次成功保存的位置或默认右侧位置。
- 管理员不能把标题或正文留空后保存；书记官不会看到编辑控件。
- 自动化覆盖：空白默认状态、管理员增改删、书记官只读、跨账号内容同步、不同账号位置独立持久化、关闭只影响当前会话、拖动边界、窄屏可见性、图标尺寸与点击区。

## 6. 动效规则

- 档案编辑器、选择器、审核窗口和其他常规工作台窗口继续复用现有桌面的统一打开、最小化和关闭动画；本次不另起一套窗口动效。
- 书记官关闭单张便签时，便签不使用窗口关闭动画，而是执行短促的“从纸条边缘撕下并离开桌面”的专属离场动效；动效结束后仅加入当前会话的隐藏集合。
- 管理员删除便签属于内容删除：先使用同一撕下动效，再在共享数据保存成功后移除。保存失败时保留原便签和编辑内容，并显示错误，不可伪装成已删除。
- 拖动便签只使用位置的即时跟随与松手落位，不触发窗口开关动画；所有动效遵守用户的 `prefers-reduced-motion` 设置。

## 7. 不改变的内容

- 不修改档案的草稿、审核、打回、正式录入、发布状态机。
- 不修改现有公开档案系统浏览体验。
- 不把便签正文混入档案正文或管理员审核批注。
- 不增加书记官的新主操作入口。
