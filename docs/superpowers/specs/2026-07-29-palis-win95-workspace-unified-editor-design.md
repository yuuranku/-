# PALIS Win95 工作台与九类统一编辑器设计规格

日期：2026-07-29

状态：待用户书面复核

选定方案：A——保留现有业务与数据合同，重做工作台操作系统壳和编辑器外壳

## 1. 目标

本次改造建立两层明确、互不串色的产品边界：

1. 外层 PALIS 档案系统是供玩家浏览的“档案馆”，负责九类目录、公开索引和正式档案阅读。
2. 内层管理员／书记官工作台是可操作的 Win95 风格桌面系统，负责新建、补充、修改、暂存、审核、录入和管理。
3. 九类编辑器在 Win95 应用窗口内使用一张连续的 PALIS 表单，不再把浅色行政表单和深色档案设定卡左右分开。

改造完成后，用户应能一眼分辨：

- “我正在浏览档案馆”；
- “我已经进入工作台操作系统”；
- “Win95 是操作系统外壳，PALIS 是档案内容本身”。

## 2. 冻结项与非目标

以下内容本次不得改变：

- 外层 PALIS 首页、九类公开目录、正式档案详情的既有美术排版与动效。
- 九类正式编号、目录编号、版本、署名、审核和发布规则。
- `EditorDocument v2` 的 `values`、`indexData`、`sections`、`fieldLabels`、`references`、`media` 数据合同。
- 本地暂存、云端暂存、审核、录入、公开投影和数据库迁移结果。
- 九份设定卡的 `[data-save]`、`.sect`、`.sect-label` 字段合同。
- 科考站、白幕入口对书记官“只能申请修改”、对管理员“可以新建和设定”的权限规则。
- 人物头像、事件封面／证据图的媒体槽规则。

本次不做：

- 不重写数据库或新增迁移。
- 不把约 477 个模板字段重新手工实现为第二套表单。
- 不增加实时协作、桌面图标自由拖动、窗口任意缩放或桌面主题切换。
- 不伪造无实际功能的菜单项、工具栏按钮或系统提示。
- 不让 Win95 风格覆盖外层档案馆。

## 3. 总体架构

### 3.1 表面分层

```text
外层 PALIS 档案馆
  ├─ 九类公开索引
  ├─ 正式档案阅读窗口
  └─ 进入工作台

内层 Win95 工作台
  ├─ 桌面快捷方式
  ├─ 开始菜单
  ├─ 任务栏与系统托盘
  ├─ PALIS 档案柜窗口
  ├─ 暂存／回信／审核／管理窗口
  └─ 九类统一编辑窗口
       └─ PALIS 单卷轴档案表单
```

### 3.2 技术边界

- 现有窗口层、窗口 Map、焦点层级、拖动、最小化和任务按钮逻辑继续使用。
- `workspace.js` 继续拥有工作流表单、索引、引用、媒体、附件和提交行为。
- 九类设定卡继续在同源 iframe 内运行，`editor-bridge.js` 继续负责读取和写入 `[data-save]`。
- 父页面仍是草稿数据的唯一所有者；不得把父表单节点直接移动进 iframe。
- iframe 只作为内部实现边界存在，视觉上不再呈现为“右侧另一套网页”。
- 数据库、仓库、发布投影和正式档案渲染器不因本次 UI 改造改变。

## 4. Win95 工作台桌面

### 4.1 桌面画面

- 使用克制的深青绿色纯色桌面，保留 PALIS 气质但不做海报式大标题。
- 右下角、任务栏上方显示小型只读水印：`PALIS LOCAL 09A`、当前角色和连接状态。
- 桌面图标采用统一的 32px 像素化文件夹／系统图标；视觉图标较小，完整点击区域不小于 72×72px。
- 图标标签使用白字和单行或最多两行排版；选中时仅标签和焦点区域变为经典深蓝底，不使用整张大卡片。
- 桌面图标从左上角开始按固定网格纵向排列；不保存用户自定义位置，以控制复杂度和避免移动端冲突。

### 4.2 桌面快捷方式

书记官桌面固定显示：

1. `PALIS 档案柜`
2. `暂存箱`
3. `审核回信`
4. `PALIS 助手`

管理员额外显示：

5. `审核与录入`
6. `档案管理`
7. `账号管理`

九类档案入口不直接铺在桌面上，统一收进 `PALIS 档案柜`。

### 4.3 桌面图标操作

| 操作 | 鼠标 | 键盘 | 触摸 |
|---|---|---|---|
| 选择图标 | 单击 | Tab 聚焦 | 不建立单独选择态 |
| 打开窗口 | 双击 | Enter / Space | 单击 |
| 切换选择 | 单击其他图标 | Tab / Shift+Tab | 直接打开目标 |
| 清除选择 | 点击桌面空白处 | Escape | 点击空白处 |

Escape 只执行“关闭当前开始菜单／取消桌面选择”，不得直接退出整个工作台。

## 5. 开始菜单

任务栏左侧按钮从“工作台”改为“开始”，并成为工作台内唯一的开始菜单入口。吉祥物不再承担第二套开始菜单职责。

菜单结构：

```text
PALIS 09A
├─ PALIS 档案柜
├─ 暂存箱
├─ 审核回信
├─ 管理工具                    仅管理员显示
│  ├─ 审核与录入
│  ├─ 档案管理
│  └─ 账号管理
├─ PALIS 助手
├─ 关于此工作台
└─ 返回档案系统
```

按钮逻辑：

- `开始`：打开或关闭菜单；`aria-expanded` 与显示状态同步。
- 菜单项目：打开对应窗口后关闭菜单。
- `管理工具`：仅管理员可见；书记官 DOM 中不得保留可聚焦的隐藏管理项。
- `关于此工作台`：打开现有欢迎／身份说明窗口。
- `返回档案系统`：显式退出工作台并返回外层档案馆；若存在未同步的编辑器，先显示确认对话框。
- 点击菜单外部或按 Escape：只关闭菜单，不退出工作台。

## 6. PALIS 档案柜

### 6.1 窗口结构

档案柜是 Win95 资源管理器式窗口：

1. 标题栏：应用图标、`PALIS 档案柜`、最小化、最大化／还原、关闭。
2. 菜单栏：只显示具有实际功能的 `文件`、`查看`、`帮助`。
3. 地址栏：只读路径 `C:\PALIS\ARCHIVES`。
4. 内容区：九个类别文件夹。
5. 状态栏：`9 个对象`、当前身份、选中类别的权限提示。

菜单行为：

- `文件 > 打开`：打开当前选中的类别；未选择时禁用。
- `文件 > 关闭`：关闭档案柜窗口。
- `查看 > 大图标`：默认且首版唯一视图；菜单项显示选中状态，不增加无效切换。
- `帮助 > 类别权限`：打开简短说明对话框。

### 6.2 九类文件夹

九个文件夹按 `01–09` 排列：

1. 国家
2. 组织
3. 科考站
4. 白幕入口
5. 生态
6. 人物
7. 事件
8. 异常
9. 物种与标本

每个文件夹显示中文名、模板缩写和当前角色可执行动作。

| 类别 | 书记官 | 管理员 |
|---|---|---|
| 国家、组织、生态、人物、事件、异常、物种 | 新建／补充同一档案／提交修改申请 | 新建／补充／修改／设定 |
| 科考站、白幕入口 | 只能选择既有档案并提交修改申请 | 新建／补充／修改／设定 |

鼠标单击选择、双击打开；键盘 Enter 打开；触摸单击打开。打开后复用现有 `createEditor(template)` 入口，不另建业务分支。

## 7. 任务栏与系统托盘

### 7.1 任务栏结构

任务栏只保留四部分：

1. `开始`
2. 已打开窗口任务按钮
3. 系统托盘
4. 时钟

移除当前常驻任务栏中的欢迎语、长身份文字、“本地工作台已接入”和“返回档案系统”按钮。

### 7.2 任务按钮

- 每个任务按钮显示 16px 应用图标和窗口标题。
- 活动窗口使用 inset 状态；非活动窗口使用 raised 状态；最小化窗口降低强调。
- 点击非活动任务：聚焦并置顶。
- 点击最小化任务：恢复并聚焦。
- 点击当前活动任务：最小化。
- 任务过多时按钮收窄并截断标题，不显示水平滚动条。

### 7.3 系统托盘

托盘包含：

- 本地／云端同步状态图标。
- 当前身份图标（书记官或管理员）。
- 时钟。

托盘状态必须同时有图标、文本提示或 tooltip，不能只依赖颜色。点击同步图标打开轻量状态对话框，不执行上传或重试等隐式写操作。

## 8. 应用窗口规范

### 8.1 视觉

- 客户区外壳使用经典 `#c0c0c0` 灰色面板和 2px bevel。
- 活动标题栏使用经典深蓝；非活动标题栏使用灰色。
- 标题栏左侧显示 16px 应用图标和标题。
- 阴影控制在 2–3px，不再使用现代大面积悬浮阴影。
- 窗口控制按钮依次为最小化、最大化／还原、关闭。

### 8.2 行为

- 单击窗口或任务按钮使其激活并提升 z-index。
- 拖动标题栏移动窗口；拖动范围不得进入任务栏下方。
- 双击标题栏或点击最大化按钮切换最大化／还原。
- 最小化隐藏窗口但保留任务按钮。
- 关闭普通窗口时移除任务按钮并恢复合理焦点。
- 关闭存在未保存／未同步内容的编辑器时先走现有离开确认逻辑。
- 不在本轮增加任意边缘缩放。

### 8.3 小屏幕

宽度不超过 760px 时：

- 应用窗口自动最大化。
- 禁止拖动和自由叠放。
- 标题栏控件提供至少 44px 触控区。
- 开始菜单从任务栏向上展开为全宽面板。
- 桌面快捷方式使用三列网格。
- 任务栏只显示开始、当前任务、精简托盘和时钟，并保留安全区。

## 9. 九类统一编辑器

### 9.1 单一信息流

编辑窗口取消永久左右分栏，改为从上到下的单一表单：

```text
应用标题栏
编录状态条
00 目录归类与索引
01…NN 当前类别的原版档案正文
关联档案
版面图片（仅人物／事件）
补充附件
归档责任与署名
粘性操作栏
```

全窗口只有一个主滚动区域。不得继续出现“父页面滚动 + iframe 内滚动”的双滚动。

### 9.2 视觉融合

- Win95 只负责标题栏、窗口边框、菜单和系统按钮。
- 编辑器客户区统一使用设定卡已有的 PALIS 深蓝、米白、芥末黄、砖红、青绿色和 CRT/bezel 语言。
- 索引、引用、图片、附件和署名都改为 PALIS 分区，不再使用独立浅灰左栏。
- 正文前显示 `00 / INDEX REGISTRATION`，正文后依次显示关联材料和归档责任。
- 桌面端提供窄型粘性分区目录；窄屏改为“当前分区 + 下拉目录”。两者只能导航，不能成为第二套输入区。

### 9.3 iframe 嵌入方式

为降低回归风险：

- 九份模板继续在 iframe 中编辑。
- `editor-bridge.js` 在嵌入时给 iframe 文档增加工作台嵌入状态并注入最小展示覆盖，不修改模板字段合同。
- 嵌入状态隐藏模板自身的打印／PNG／清空操作条，避免与工作台操作重复。
- 独立打开模板时，原打印、PNG 和清空功能继续存在。
- 父页面根据同源 iframe 的内容高度自动调整 iframe 高度，并在内容变化时重新测量。
- iframe 自身不出现滚动条；滚动由统一编辑器客户区承担。
- 若高度同步失败，回退到明确标记的正文滚动区并显示错误提示，不能让正文不可达。

### 9.4 索引与正文去重

以下同步字段在界面上只允许出现一个主要录入位置：

- 九类标题：`indexData.title ↔ hero`
- 科考站／白幕入口坐标：索引经纬度 ↔ 模板坐标
- 物种分类：`specimenClass` ↔ 模板植物／动物／复合群落
- 事件开始时间：`startDate` ↔ 模板事件时间

主要录入位置设在 `00 目录归类与索引`。模板对应字段只在工作台嵌入状态下改为只读，显示同步结果并标记为“由目录索引同步”；独立打开模板时仍维持原编辑能力。同步实现必须防止循环写入，并继续使用标准化后的索引值。

其他未建立可靠一对一映射的字段不得自动猜测或按同名文字批量同步。

### 9.5 编录方式

顶部状态条包含：

- 编录方式
- 目标档案／目标具体文档（需要时显示）
- 正式档号（只读，审核录入时生成）
- 本地／云端保存状态

三种方式：

| 方式 | 正文 | 结果 |
|---|---|---|
| 新建档案 | 对应类别的完整空白设定卡 | 新上层档案和记录 01 |
| 补充同一档案 | 对应类别的完整空白设定卡 | 同一上层档案中的下一份独立记录 |
| 提交修改申请 | 自由修订补充页 | 修改指定具体文档，不新建同级记录 |

书记官进入科考站或白幕入口时，方式固定为“提交修改申请”，且必须选择目标档案和目标具体文档。管理员不受此限制。

### 9.6 分区与按钮逻辑

`立即暂存`：

- 立即收集索引、正文、引用、媒体元数据和附件状态。
- 先写本地，再尝试云端。
- 云端失败时保留本地内容并给出可恢复提示。
- 保存期间按钮禁用，完成后恢复。

`提交审核`：

- 先执行索引、目标档案、目标文档和正文最低要求校验。
- 错误显示在对应字段附近，并聚焦第一个错误。
- 人物／事件存在待上传图片时，先完成受控上传或明确中止。
- 提交成功后锁定当前编辑器，显示投稿编号和“已提交审核”确认状态；用户确认结果后再自行关闭窗口。
- 提交失败不得清空本地草稿。

`单独打开`：

- 在新标签打开当前模板的独立版本。
- 不携带当前父页面中的未保存附件对象。
- 明确提示独立页面只用于查看／导出，不替代工作台提交。

模板内部的 `打印 / 导出 PDF`、`导出 PNG`、`清空`：

- 嵌入工作台时隐藏。
- 独立打开时保持现状。

## 10. 错误、恢复与权限

- 索引错误显示在字段旁，并在分区标题显示错误数量。
- iframe 加载失败时显示“重新载入正文”按钮；索引和已保存草稿仍可访问。
- 离线时继续本地保存，托盘和状态条同时显示离线状态。
- 会话失效时禁止云端提交，但不得删除本地草稿。
- 管理员专用入口在书记官界面不可见、不可聚焦，业务处理器继续二次校验权限。
- 对固定类别的非法新建请求在 UI 和领域层都拒绝。
- 关闭未同步编辑器、返回档案系统或切换身份前必须进入离开确认。
- 确认对话框必须说明将保留什么、可能丢失什么，以及“继续编辑／保存后离开／放弃本地未保存修改”三个真实动作。

## 11. 性能与免费服务器影响

本次为界面重排，不增加数据库表、轮询或公开目录请求。

- 档案柜只加载九类模板元数据，不预载九份大型 HTML。
- 只有打开编辑器时才加载当前一份模板 iframe。
- 保持现有 800ms 本地暂存和 5s 云端防抖，不因布局变化增加写入频率。
- iframe 高度监听只观察当前正文根节点，并在动画帧中合并更新，避免连续重排。
- 桌面图标使用本地 SVG／像素资源，不请求外部图标服务。
- 人物／事件图片继续使用现有压缩和槽位上限。
- 外层公开目录继续只读取索引投影，不读取完整正文。

因此本次改造不会提高 Supabase 数据库存储、出口或写入压力；主要新增成本仅为浏览器端布局和当前单个 iframe 的高度计算。

## 12. 可访问性

- 所有桌面图标、菜单项、窗口按钮和表单字段具有可读名称。
- 标题栏控制按钮的视觉符号与 `aria-label` 同时存在。
- Tab 顺序与视觉顺序一致；Enter／Space 可打开当前项目。
- 焦点环始终可见，不只依赖颜色。
- 错误使用 `role="alert"` 或合适的 live region。
- 正常文字对比度不低于 4.5:1。
- 只读系统字段在视觉和语义上与 disabled 字段区分。
- 保留 `prefers-reduced-motion`；本轮不新增装饰性动画。
- 触摸目标在小屏幕上不小于 44px。

## 13. 预计修改边界

主要修改：

- `index.html`：桌面快捷方式、开始菜单、任务栏、档案柜宿主结构。
- `src/style.css`：桌面、开始菜单、任务栏和通用窗口 Win95 视觉。
- `src/main.js`：唯一开始菜单入口、桌面选择／打开、退出行为、最大化状态。
