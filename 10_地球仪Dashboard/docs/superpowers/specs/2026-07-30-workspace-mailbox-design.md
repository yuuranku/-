# 工作台邮箱设计

## 目标

将书记官桌面右侧的信封入口升级为正式邮箱。审核回复仍自动投递给对应投稿书记官；管理员还可以向任一书记官发送系统公告。

## 方案

- 保留 `archive_notifications` 作为唯一收件箱数据源，新增 `announcement` 通知类型；公告没有关联投稿。
- 管理员打开邮箱时看到收件和“发送公告”表单；表单只列出启用的书记官。书记官打开同一入口时只看到自己的收件箱。
- 邮箱按时间倒序展示，包含主题、正文、时间和清晰的类别标签；没有投稿关联的公告显示“PALIS 档案管理处”。不显示管理员邮箱或账户信息。
- 未读提示继续使用现有红点；审核队列提示与管理员个人邮件未读一起生效。
- 使用现有 Windows 风格窗口、按钮、图标和通知表，不重做工作台视觉系统。

## 安全与失败处理

- 浏览器只在当前角色为管理员时显示发送表单；数据库通过既有 RLS 管理员插入策略再次限制发送权限。
- 接收人必须是启用的书记官；主题和正文在本地校验非空、限长，并在数据库函数中再次校验。
- 发送失败时保留表单输入并显示错误；成功后清空表单并刷新未读状态。

## 验证

- 本地工作流测试管理员可向指定书记官发送公告、其他书记官不可读取。
- UI 合同测试确认邮箱入口、管理员发送面板、审核回复路径都存在。
- 运行完整测试和生产构建，再应用数据库迁移并部署。
