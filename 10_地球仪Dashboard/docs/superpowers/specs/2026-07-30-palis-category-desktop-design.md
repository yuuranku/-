# PALIS 九项档案桌面入口设计

## 目标

把书记官桌面的档案入口改为“类别优先”：九项档案类别直接以像素化桌面图标竖排展示；点击类别后，才选择修改或新增。

## 范围

- 桌面显示国家、组织、科考站、白幕入口、生态、人物、事件、异常、物种九项档案图标。
- 图标采用复古 Win95 小程序式的像素图形、灰白立体边框和类别识别色；不使用当前大号白底文件图标。
- 九项按单列竖排，超出可视高度时沿桌面区域滚动。
- 移除桌面的全局“新增档案”和“修改档案”入口，避免动作入口与类别入口并存。
- 点击任一类别图标，打开该类别的窄竖向操作窗口：上方“修改”、下方“新增”。
- “新增”先提供“建立独立档案”与“为既有档案新增正文”两种同类别目标：前者建立新的档案容器，后者选择现有档案容器后新建一份空白、独立的正文。
- 此规则适用于全部九类。HZ-6 已有一份事件正文时，另一位书记官可在“事件 → 新增”中选择 HZ-6 并建立第二份正文；国家、组织、科考站等任何既有档案也同样可新增并列正文。审核通过后，各正文都归属原档案、并列保留提交者与各自的版本历史。
- “修改”只列出当前类别的已发布档案与其正文；它从选定正文带入现有内容，提交后只增加该正文自己的修订版本，不会生成并列正文。
- 被管理员打回的新增稿保留在该类别的“新增”内；被打回的修改稿保留在该类别的“修改”内。两处继续显示管理员批注。
- 审核与录入、档案管理、账号管理、权限限制、窗口动画、拖动与滚轮行为均不改变。

## 交互流

```text
书记官桌面
  -> 九项类别图标（竖排）
    -> 某一类别
      -> 修改：读取该类别已发布档案及其正文 / 返回修改稿
      -> 新增：建立独立档案，或选择既有档案后新增一份并列正文 / 返回新增稿
        -> 提交审核 -> 管理员通过或打回 -> 档案系统上线或回到原入口
```

## 技术边界

- 复用 `ARCHIVE_TEMPLATES` 作为九项类别的唯一来源，避免另建固定清单。
- 将现有 `openNewArchiveChooser` 与 `openModifyArchiveChooser` 的类别选择层收敛为类别操作窗口；新增既有档案正文复用已有 `contribution` 类型，下层的编辑器、草稿归属、档案读取逻辑不重写。
- 为桌面类别命令与类别操作窗口补充浏览器回归测试：顺序、竖排、正确的新增/修改分流、打回稿归属。

## 验收

1. 书记官桌面可直接看到九项类别，且没有全局“新增档案 / 修改档案”图标。
2. 事件图标打开后，“修改”在上、“新增”在下；两者都只处理事件档案。
3. 任一类别的既有档案都可在“新增”中选择并建立第二份独立正文；HZ-6 是事件类别的示例。批准后两份都显示在同一档案内。
4. 修改任一正文时，只增加该正文的修订版本，不覆盖同档案下的其他正文。
5. 九类都同样遵循这一流向；打回稿与批注仍在所属动作内可见。
6. 管理员和只读账号的既有限制不回退。
